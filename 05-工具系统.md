# 第5章：工具系统

工具系统是 Claude Code 与外部世界交互的核心机制。通过工具，Claude 模型能够读取文件、执行命令、搜索代码、启动子代理等。本章将深入分析 Claude Code 的工具定义、注册机制、各类核心工具的实现原理，以及权限控制体系。

## 5.1 工具定义与注册

### 5.1.2 buildTool 工厂函数

`buildTool` 是创建工具的核心工厂函数，它为常用方法提供安全默认值：

```typescript
// src/Tool.ts
const TOOL_DEFAULTS = {
  isEnabled: () => true,
  isConcurrencySafe: (_input?: unknown) => false,  // 默认不安全
  isReadOnly: (_input?: unknown) => false,          // 默认写操作
  isDestructive: (_input?: unknown) => false,
  checkPermissions: (input, _ctx) =>
    Promise.resolve({ behavior: 'allow', updatedInput: input }),
  toAutoClassifierInput: (_input?: unknown) => '',
  userFacingName: (_input?: unknown) => '',
}

export function buildTool<D extends AnyToolDef>(def: D): BuiltTool<D> {
  return {
    ...TOOL_DEFAULTS,
    userFacingName: () => def.name,
    ...def,
  } as BuiltTool<D>
}
```

**默认值策略**（fail-closed 原则）：
- `isConcurrencySafe` 默认 `false` —— 假设不安全
- `isReadOnly` 默认 `false` —— 假设是写操作
- `checkPermissions` 默认允许 —— 委托给通用权限系统

### 5.2.2 FileWriteTool —— 文件写入

**位置**：`src/tools/FileWriteTool/FileWriteTool.ts`

FileWriteTool 用于创建新文件或完全覆盖现有文件。

**输入 Schema**：

```typescript
const inputSchema = lazySchema(() =>
```

**写入前验证流程**：

```typescript
async validateInput({ file_path, content }, toolUseContext: ToolUseContext) {
  const fullFilePath = expandPath(file_path)

  // 1. 检查是否包含敏感信息
  const secretError = checkTeamMemSecrets(fullFilePath, content)
  if (secretError) return { result: false, message: secretError, errorCode: 0 }

  // 2. 检查权限拒绝规则
  const denyRule = matchingRuleForInput(fullFilePath, appState.toolPermissionContext, 'edit', 'deny')
  if (denyRule !== null) {
    return { result: false, message: 'File is in a directory denied by your permission settings.', errorCode: 1 }
  }

  // 3. UNC 路径安全检查（防止 NTLM 凭证泄露）
  if (fullFilePath.startsWith('\\\\') || fullFilePath.startsWith('//')) {
    return { result: true }
  }

  // 4. 检查文件是否已被读取（防止覆盖未查看的内容）
  const readTimestamp = toolUseContext.readFileState.get(fullFilePath)
  if (!readTimestamp || readTimestamp.isPartialView) {
    return { result: false, message: 'File has not been read yet. Read it first before writing to it.', errorCode: 2 }
  }

  // 5. 检查文件是否被外部修改
  const lastWriteTime = getFileModificationTime(fullFilePath)
  if (lastWriteTime > readTimestamp.timestamp) {
    return { result: false, message: 'File has been modified since read...', errorCode: 3 }
  }

  return { result: true }
}
```

**原子写入机制**：

```typescript
async call({ file_path, content }, context, _, parentMessage) {
  const fullFilePath = expandPath(file_path)
  const dir = dirname(fullFilePath)

  // 1. 发现并激活相关技能
  const newSkillDirs = await discoverSkillDirsForPaths([fullFilePath], cwd)
  addSkillDirectories(newSkillDirs).catch(() => {})
  activateConditionalSkillsForPaths([fullFilePath], cwd)

  // 2. 诊断追踪
  await diagnosticTracker.beforeFileEdited(fullFilePath)

  // 3. 确保父目录存在（原子写入的关键）
  await getFsImplementation().mkdir(dir)

  // 4. 文件历史备份
  if (fileHistoryEnabled()) {
    await fileHistoryTrackEdit(updateFileHistoryState, fullFilePath, parentMessage.uuid)
  }

  // 5. 原子读取-修改-写入
  // 避免在此处与写入磁盘之间进行异步操作以保持原子性
  const meta = readFileSyncWithMetadata(fullFilePath)
  if (meta !== null) {
    const lastWriteTime = getFileModificationTime(fullFilePath)
    const lastRead = readFileState.get(fullFilePath)
    if (!lastRead || lastWriteTime > lastRead.timestamp) {
      // 内容比较回退（Windows 时间戳问题）
      if (meta.content !== lastRead.content) {
        throw new Error(FILE_UNEXPECTEDLY_MODIFIED_ERROR)
      }
    }
  }

  // 6. 写入文件（保留 LF 行尾）
  writeTextContent(fullFilePath, content, enc, 'LF')

  // 7. 通知 LSP 服务器
  const lspManager = getLspServerManager()
  if (lspManager) {
    clearDeliveredDiagnosticsForFile(`file://${fullFilePath}`)
    lspManager.changeFile(fullFilePath, content).catch(...)
    lspManager.saveFile(fullFilePath).catch(...)
  }

  // 8. 通知 VSCode
  notifyVscodeFileUpdated(fullFilePath, oldContent, content)

  // 9. 更新读取时间戳
  readFileState.set(fullFilePath, { content, timestamp: getFileModificationTime(fullFilePath), ... })
}
```

**编辑验证流程**：

```typescript
async validateInput(input: FileEditInput, toolUseContext: ToolUseContext) {
  const { file_path, old_string, new_string, replace_all = false } = input

  // 1. 检查新旧字符串是否相同
  if (old_string === new_string) {
    return { result: false, message: 'No changes to make: old_string and new_string are exactly the same.', errorCode: 1 }
  }

  // 2. 检查文件大小限制（防止 OOM）
  const { size } = await fs.stat(fullFilePath)
  if (size > MAX_EDIT_FILE_SIZE) { // 1 GiB
    return { result: false, message: `File is too large to edit (${formatFileSize(size)})...`, errorCode: 10 }
  }

  // 3. 检查文件是否存在
  if (fileContent === null) {
    if (old_string === '') {
      return { result: true } // 创建新文件
    }
    return { result: false, message: `File does not exist...`, errorCode: 4 }
  }

  // 4. 检查是否需要先读取
  const readTimestamp = toolUseContext.readFileState.get(fullFilePath)
  if (!readTimestamp || readTimestamp.isPartialView) {
    return { result: false, message: 'File has not been read yet...', errorCode: 6 }
  }

  // 5. 查找目标字符串
  const actualOldString = findActualString(file, old_string)
  if (!actualOldString) {
    return { result: false, message: `String to replace not found in file.\nString: ${old_string}`, errorCode: 8 }
  }

  // 6. 检查多重匹配
  const matches = file.split(actualOldString).length - 1
  if (matches > 1 && !replace_all) {
    return { result: false, message: `Found ${matches} matches...set replace_all to true.`, errorCode: 9 }
  }

  return { result: true, meta: { actualOldString } }
}
```

```typescript
  if (limit === 0) {
    return { items: items.slice(offset), appliedLimit: undefined } // 无限制
  }
  const effectiveLimit = limit ?? DEFAULT_HEAD_LIMIT
  const sliced = items.slice(offset, offset + effectiveLimit)

}
```

```typescript
  const args = ['--hidden']

  // 添加 VCS 排除
  for (const dir of VCS_DIRECTORIES_TO_EXCLUDE) {
    args.push('--glob', `!${dir}`)
  }

  // 限制行长度
  args.push('--max-columns', '500')

  // 输出模式
  if (output_mode === 'files_with_matches') args.push('-l')
  else if (output_mode === 'count') args.push('-c')
  if (show_line_numbers && output_mode === 'content') args.push('-n')

  // 上下文
  if (context !== undefined) args.push('-C', context.toString())

  // 执行搜索
  const results = await ripGrep(args, absolutePath, abortController.signal)

  // 按修改时间排序（files_with_matches 模式）
  const stats = await Promise.allSettled(results.map(_ => getFsImplementation().stat(_)))
  const sortedMatches = results
    .map((_, i) => [_, r.status === 'fulfilled' ? r.value.mtimeMs ?? 0 : 0])
    .sort((a, b) => b[1] - a[1])
    .map(_ => _[0])

  // 应用分页并相对化路径
  const { items: finalMatches, appliedLimit } = applyHeadLimit(sortedMatches, head_limit, offset)
  const relativeMatches = finalMatches.map(toRelativePath)

  return { data: { mode: output_mode, filenames: relativeMatches, numFiles: relativeMatches.length, ... } }
}
```

## 小结

Claude Code 的工具系统是一个设计精良的插件式架构：

1. **统一的工具接口**：通过 `Tool` 类型和 `buildTool` 工厂函数，所有工具遵循一致的定义模式

2. **类型安全**：使用 Zod schema 定义输入输出，结合 TypeScript 泛型提供完整的类型推导

3. **安全优先**：
   - 文件操作前必须先读取（防止盲目覆盖）
   - 沙盒隔离命令执行
   - 危险文件/目录保护
   - 多层权限检查

4. **性能优化**：
   - 文件状态缓存与去重
   - 结果分页与截断
   - 路径相对化以节省令牌

5. **可扩展性**：
   - Agent 子代理系统支持任务并行
   - Skill 技能系统支持工作流复用
   - MCP 协议支持外部工具集成
